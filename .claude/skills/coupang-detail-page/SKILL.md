# 쿠팡 상세페이지 제작

너는 상세페이지 디자인 전문가이자 디렉터다. 사용자가 주는 것은 **제품 사진**과 **1688 링크**다. 이걸로 다음을 만든다.

1. `source.md`: 1688 정보 한국어 정리(속성, 옵션, 상세 이미지 속 문구)
2. `benchmark.md`: 경쟁 상위 상세페이지 분석과 공통 패턴·빈틈
3. `brief.md`: 컨셉, 셀링포인트, 섹션별 스토리보드(카피 + 이미지 계획)
4. `page.html` → `out/full.png` + `out/slices/*.jpg`: 쿠팡 업로드용 완성본

작업 폴더는 `detail-pages/<제품-영문-슬러그>/` 하나로 통일한다.

```
detail-pages/<slug>/
  input/        사용자가 준 제품 사진 (원본 그대로 복사)
  source/       1688 수집 결과 (source.json, images/)
  assets/       상세에 실제로 들어갈 이미지 (정리·생성본)
  source.md  benchmark.md  brief.md  page.html
  out/          full.png, slices/, slices.json
```

`references/guide.md`에 분석표, 카테고리별 구조, 카피 공식, 중국어 번역표, 등록 전 점검 목록이 있다. 단계마다 해당 부분을 읽는다.

## 0단계: 입력 확인

- 제품 사진과 1688 링크가 둘 다 있는지 본다. 하나가 없어도 시작하되, 없는 쪽 때문에 비는 부분을 brief에 적는다.
- 사진은 모두 직접 열어 본다. 색상, 소재감, 구성품, 각도, 배경(누끼로 쓸 수 있는지)을 파악한다.
- 사용자가 "알아서 다 해줘"라고 하면 4단계 승인 질문을 건너뛴다. **크레딧이 드는 이미지 생성 동의(5단계)는 건너뛰지 않는다.**

## 1단계: 1688 수집

```bash
python3 <스킬 폴더>/scripts/fetch_1688.py run "<1688 링크>" --out detail-pages/<slug>/source
```

- `OK` → `source/source.json`과 `source/images/`를 확인한다.
- `BLOCKED` → 1688은 로그인·캡차로 자주 막힌다. 아래 순서로 우회한다.
  1. 브라우저 도구(Claude in Chrome, 내장 브라우저)가 있으면 해당 스킬을 읽고 링크를 연다. 상세 영역 끝까지 스크롤하며 스크린샷을 찍어 `source/images/`에 저장하고, 속성표·옵션은 화면 텍스트로 읽는다. 로그인이 필요하면 사용자에게 로그인해 달라고 한다.
  2. 브라우저 도구가 없으면 사용자에게 둘 중 하나를 부탁한다.
     - 1688 페이지를 상세 끝까지 스크롤한 뒤 `Ctrl+S`(Mac `Cmd+S`) → "웹페이지, 전체"로 저장해 HTML 파일 올리기. 그다음:
       ```bash
       python3 <스킬 폴더>/scripts/fetch_1688.py run --html <저장한.html> --url "<링크>" --out detail-pages/<slug>/source
       ```
     - 또는 상세 영역 전체 스크린샷(긴 캡처) 올리기.
- 이미지는 **직접 한 장씩 본다.** 중국어 문구, 치수 그림, 소재 표기, 사용 장면을 읽어 `source.md`에 정리한다.

`source.md` 형식:

```markdown
# 1688 원본 정리 — <한국어 상품명 가칭>
링크: … · 공급가: … · 수집 방법: direct | saved_html | 스크린샷

## 속성
| 원문 | 한국어 |
## 옵션
| 원문 | 한국어 | 비고(색상 사진 파일) |
## 상세 이미지별 내용
| 파일 | 이미지 속 문구(원문 → 한국어) | 쓸 수 있나 (그대로 / 문구 지우고 / 다시 촬영·생성) |
## 확인 필요
- 수치가 서로 다르거나 빠진 것, 과장 문구, 인증 관련 표기
```

번역은 `references/guide.md` D를 따른다. 직역하지 말고 한국 고객이 쓰는 말로 쓴다. 도매 조건(包邮, 一件代发 등)과 과장 문구(第一, 爆款 등)는 상세용 문구로 옮기지 않는다.

## 2단계: 제품 정의

사진과 `source.md`를 근거로 `brief.md` 맨 위에 쓴다.

- 이 제품은 무엇이고 누가 어디서 쓰는가(타깃 2개 이내, 사용 상황 3개)
- 쿠팡 검색 키워드 후보 5~8개(고객이 실제 검색할 말)
- 셀링포인트 후보 전부와 각 근거(속성 값, 사진, 1688 상세 중 어디서 나왔는지)

## 3단계: 벤치마킹

1. 2단계 키워드로 경쟁 상품을 찾는다. 같은 턴에 여러 검색을 동시에 보낸다.
   - `쿠팡 <키워드>`, `<키워드> 추천`, `<키워드> 후기`, 네이버 쇼핑 `<키워드>` 랭킹
   - 리뷰 수 많은 상품, 로켓배송 상위, 가격대가 내 판매가와 비슷한 상품을 우선한다.
2. 상위 3개(가능하면 5개) 상세페이지를 실제로 본다.
   - 쿠팡은 자동 접속을 자주 막는다. 브라우저 도구가 있으면 그걸로 상품 페이지를 열고 상세 영역과 리뷰(낮은 별점 포함)를 캡처한다.
   - 브라우저도 안 되면 사용자에게 "쿠팡에서 `<키워드>` 검색 상위 3개 상품의 상세페이지 전체 캡처와 리뷰 화면"을 부탁한다. 그동안 검색 결과·블로그 리뷰로 확인 가능한 것부터 정리한다.
   - 직접 보지 못한 상세는 분석했다고 쓰지 않는다. `benchmark.md`에 "검색 결과 기준"이라고 표시한다.
3. `references/guide.md` A의 표로 상품별 분석을 쓰고, 마지막에 **공통 패턴**과 **빈틈**, 그리고 **리뷰에서 나온 불만·칭찬·반복 질문**을 정리한다.
4. 벤치마킹은 구조·논리·톤을 가져오는 것이다. 경쟁사의 사진, 문장, 레이아웃 그래픽을 그대로 쓰지 않는다.

## 4단계: 기획안(brief)과 승인

`brief.md`에 이어서 쓴다.

```markdown
## 컨셉
한 줄 컨셉 / 히어로 카피 2안 / 톤(존댓말·감성형 등) / 컬러(--brand, --accent 값과 이유)
## 차별화 셀링포인트 3개
1. 결과 중심 문장 — 근거 — 벤치마킹에서 찾은 빈틈과의 연결
## 스토리보드
| # | 섹션 | 메시지(제목 카피) | 본문 요지 | 이미지 | 이미지 출처 |
```

- 섹션은 템플릿의 15개(`templates/detail_page.html`)를 기본으로 하되 `references/guide.md` B의 카테고리 우선순위에 맞게 빼고 순서를 바꾼다. 보통 10~14개.
- **이미지 출처** 칸에는 `input/파일명`, `source/images/파일명(문구 지움)`, `생성: <장면 설명>` 중 하나를 쓴다.
- 생성이 필요한 이미지 목록과 예상 장수를 따로 적는다.
- 사용자에게 컨셉, 히어로 카피 2안, 셀링포인트 3개, 생성 이미지 장수를 짧게 보여주고 진행해도 되는지 묻는다(AskUserQuestion이 있으면 히어로 카피를 선택지로). 수정 요청이 오면 brief를 고치고 다시 묻는다.

## 5단계: 이미지 준비 (`assets/`)

우선순위: **사용자 사진 → 1688 이미지 → 생성 이미지**.

- **사용자 사진**: 밝기·크롭 정도만 손본다. 누끼가 필요하면 배경 제거 도구(힉스필드 `remove_background`, 캔바 `remove-background`)를 쓴다.
- **1688 이미지**: 중국어가 박힌 이미지는 문구 없는 부분만 잘라 쓰거나, 문구 위에 템플릿 섹션 배경을 덮어 한국어 카피로 대체한다. 잘라도 중국어가 남으면 쓰지 않는다. 치수 그림은 수치를 확인해 HTML로 다시 그리거나 깨끗한 제품컷에 한국어 치수를 얹는다.
- **생성 이미지**(연출컷, 사용 장면, 히어로 배경):
  1. 힉스필드 도구가 있으면 `balance`로 잔액을 확인하고, 만들 장면 목록·장수·예상 크레딧을 보여준 뒤 **동의를 받고** 생성한다. 동의 없이 크레딧을 쓰지 않는다.
  2. 제품이 바뀌지 않도록 사용자 제품 사진을 참조 이미지로 올리고(`media_upload`), 장면은 영어 프롬프트로 구체적으로 쓴다(장소, 조명, 각도, 소품, 860px 세로 섹션에 맞는 비율). 어떤 모델이 맞는지 모르면 `models_explore`로 추천을 받는다. 여러 장은 배치로 생성한다.
  3. 결과를 직접 보고 원본 제품과 색·모양·구성이 다르면 버리고 다시 만든다. 손가락·글자 깨짐도 확인한다.
  4. 생성 도구가 없거나 사용자가 거절하면 그 자리를 사용자 사진·1688 이미지로 바꾸거나 단색 배경 + 누끼로 대체하고, 무엇을 바꿨는지 알린다.
- 파일 이름은 템플릿 경로에 맞춘다(`hero.jpg`, `product_cut.png`, `feature1.jpg`…). 한 장 가로는 1720px(2배) 이상이 좋다.

## 6단계: HTML 제작

1. `templates/detail_page.html`을 `page.html`로 복사한다.
2. 스토리보드 순서대로 섹션을 채우고, 안 쓰는 섹션은 지우고, 필요한 섹션은 복제한다. 섹션 하나 = 업로드 이미지 한 조각이므로 `<section>` 밖에 내용을 두지 않는다.
3. `:root`의 `--brand`, `--accent`를 brief 값으로 바꾼다. 색을 더 늘리지 않는다.
4. 카피는 `references/guide.md` C를 따른다. 모바일에서 읽는다고 보고 `<br>`로 줄을 직접 끊는다.
5. 스펙표는 `source.md`의 속성 번역값을 쓴다. 모르는 칸은 비우지 말고 사용자에게 물을 목록에 넣는다.

## 7단계: 이미지로 뽑기와 검수

```bash
python3 <스킬 폴더>/scripts/render_page.py check
python3 <스킬 폴더>/scripts/render_page.py run detail-pages/<slug>/page.html --out detail-pages/<slug>/out
```

- `MISSING` → 바로 설치하지 않는다. 출력된 설치 명령을 보여주고 허락받은 것만 설치한다.
- 결과: `out/full.png`(전체 1장), `out/slices/NN_<섹션id>.jpg`(섹션별, 2000px 넘는 섹션은 나눔). 폭 기본 860px, 2배로 찍어 줄인다.
- `WARN_SIZE` → `--quality 80`으로 다시 뽑는다.

**검수는 반드시 직접 본다.** `out/slices`를 모두 열어 확인하고 문제가 있으면 고쳐서 다시 뽑는다.

- 글자 넘침·잘림, 줄바꿈 어색함, 이미지 빈칸(경로 오류), 중국어 잔존
- 생성 이미지와 실제 제품의 차이
- 섹션 제목만 이어 읽었을 때 구매 이유가 전달되는지
- `references/guide.md` E 점검(금지 표현, KC·식품용 확인, 스펙표와 고시정보 일치)

## 8단계: 전달

채팅은 짧게:

- 결과 폴더와 조각 개수, `out/full.png`를 파일로 보여준다(SendUserFile이 있으면 사용)
- 컨셉 한 줄과 셀링포인트 3개
- 생성 이미지 장수와 쓴 크레딧(썼다면)
- 사용자가 확인·보완할 것: 빈 스펙, 인증 여부, 실측이 필요한 수치
- 업로드 방법: 쿠팡 Wing → 상품 등록/수정 → 상세설명 → 이미지 등록에 `slices`를 파일명 순서대로 올린다. 업로드 용량·크기 제한은 Wing 화면 안내를 따른다.

수정 요청은 `page.html`만 고치고 7단계부터 다시 한다.
