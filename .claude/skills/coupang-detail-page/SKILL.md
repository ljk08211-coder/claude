# 쿠팡 상세페이지 제작

너는 상세페이지 디자인 전문가이자 디렉터다. 사용자가 주는 것은 **제품 사진**과 **1688 링크**다. 이걸로 다음을 만든다.

1. `source.md`: 1688 정보 한국어 정리(속성, 옵션, 상세 이미지 속 문구)
2. `benchmark.md`: 쿠팡·네이버쇼핑 경쟁 상위 상세페이지 분석과 공통 패턴·빈틈
3. `brief.md`: 컨셉, 셀링포인트, 섹션별 스토리보드(카피 + 이미지 계획)
4. `page.html` → `out/full.png` + `out/slices/*.jpg`: 쿠팡 업로드용 완성본

작업 폴더는 `detail-pages/<제품-영문-슬러그>/` 하나로 통일한다.

```
detail-pages/<slug>/
  input/        사용자가 준 제품 사진 (원본 그대로 복사)
  source/       1688 수집 결과 (source.json, images/, saved.html)
  benchmark/    경쟁 상세페이지 캡처 (분석용)
  assets/       상세에 실제로 들어갈 이미지 (정리·생성본)
  source.md  benchmark.md  brief.md  page.html
  out/          full.png, slices/, slices.json
```

`references/guide.md`에 분석표, 카테고리별 구조, 카피 공식, 중국어 번역표, 등록 전 점검 목록이 있다. 단계마다 해당 부분을 읽는다.

## 0단계: 입력 확인

- 제품 사진과 1688 링크가 둘 다 있는지 본다. 하나가 없어도 시작하되, 없는 쪽 때문에 비는 부분을 brief에 적는다.
- 사진은 모두 직접 열어 본다. 색상, 소재감, 구성품, 각도, 배경(누끼로 쓸 수 있는지)을 파악한다.
- 사용자가 "알아서 다 해줘"라고 하면 4단계 승인 질문을 건너뛴다. **크레딧이 드는 이미지 생성 동의(5단계)는 건너뛰지 않는다.**

## 1단계: 1688 수집

```bash
python3 <스킬 폴더>/scripts/fetch_1688.py run "<1688 링크>" --out detail-pages/<slug>/source
```

- `OK` → `source/source.json`과 `source/images/`를 확인한다.
- `BLOCKED` 또는 `NO_IMAGES` → 1688은 로그인·캡차로 자주 막힌다. **바로 HTML 방식으로 바꾼다.** 사용자에게 이렇게 안내한다.

  > 1688이 자동 접속을 막아서 페이지를 저장한 HTML 파일로 진행할게요.
  > 1. 크롬에서 1688에 로그인한 뒤 상품 링크를 엽니다.
  > 2. 상세 이미지가 다 뜨도록 페이지 맨 아래까지 천천히 스크롤합니다.
  > 3. `Ctrl+S`(Mac `Cmd+S`) → 형식 "웹페이지, 전체"로 저장합니다.
  > 4. 저장된 `.html` 파일을 올려 주세요. (같이 생긴 `_files` 폴더는 없어도 됩니다)

  파일을 받으면 `source/saved.html`로 복사하고 실행한다.

  ```bash
  python3 <스킬 폴더>/scripts/fetch_1688.py run --html detail-pages/<slug>/source/saved.html --url "<링크>" --out detail-pages/<slug>/source
  ```

  - 저장 HTML에서도 이미지가 안 나오면(이미지 서버까지 막힌 경우) `_files` 폴더 안 이미지를 함께 받거나, 상세 영역 긴 스크린샷을 부탁한다.
  - 브라우저 도구(Claude in Chrome, 내장 브라우저)가 연결돼 있으면 사용자 수고를 덜기 위해 그걸로 페이지를 열어 저장·캡처해도 된다. 해당 스킬을 먼저 읽는다.
- 이미지는 **직접 한 장씩 본다.** 중국어 문구, 치수 그림, 소재 표기, 사용 장면을 읽어 `source.md`에 정리한다.

`source.md` 형식:

```markdown
# 1688 원본 정리 — <한국어 상품명 가칭>
링크: … · 공급가: … · 수집 방법: direct | saved_html | 스크린샷

## 속성
| 원문 | 한국어 |
## 옵션
| 원문 | 한국어 | 비고(색상 사진 파일) |
## 상세 이미지별 내용
| 파일 | 이미지 속 문구(원문 → 한국어) | 쓸 수 있나 (그대로 / 문구 지우고 / 다시 촬영·생성) |
## 확인 필요
- 수치가 서로 다르거나 빠진 것, 과장 문구, 인증 관련 표기
```

번역은 `references/guide.md` D를 따른다. 직역하지 말고 한국 고객이 쓰는 말로 쓴다. 도매 조건(包邮, 一件代发 등)과 과장 문구(第一, 爆款 등)는 상세용 문구로 옮기지 않는다.

## 2단계: 제품 정의

사진과 `source.md`를 근거로 `brief.md` 맨 위에 쓴다.

- 이 제품은 무엇이고 누가 어디서 쓰는가(타깃 2개 이내, 사용 상황 3개)
- 쿠팡 검색 키워드 후보 5~8개(고객이 실제 검색할 말)
- 셀링포인트 후보 전부와 각 근거(속성 값, 사진, 1688 상세 중 어디서 나왔는지)

## 3단계: 벤치마킹

벤치마킹 대상은 **쿠팡과 네이버쇼핑을 둘 다** 찾는다. 쿠팡은 실제 경쟁 상대, 네이버(스마트스토어·브랜드스토어)는 상세페이지 완성도가 높은 곳이 많아 디자인·구성 참고용으로 좋다.

1. 2단계 키워드로 경쟁 상품을 찾는다. 같은 턴에 여러 검색을 동시에 보낸다.
   - 쿠팡: `site:coupang.com <키워드>`, `쿠팡 <키워드> 추천`, `쿠팡 <키워드> 랭킹`
   - 네이버쇼핑: `site:smartstore.naver.com <키워드>`, `site:brand.naver.com <키워드>`, `네이버쇼핑 <키워드> 베스트`
   - 보조: `<키워드> 추천 비교`, `<키워드> 후기 단점`(블로그·카페 리뷰), 필요하면 11번가·G마켓·오늘의집(인테리어·생활용품)
   - 리뷰 수 많은 상품, 쿠팡 로켓배송 상위, 네이버 리뷰 많은 스토어, 가격대가 내 판매가와 비슷한 상품을 우선한다.
2. **쿠팡 2~3개 + 네이버 2~3개**, 합쳐 4~6개 상세페이지를 실제로 본다.
   - 상품 페이지를 직접 열어(WebFetch) 상세 이미지 주소를 찾고, 이미지를 받아 직접 본다. 네이버 스마트스토어는 상세 이미지가 페이지에 그대로 실려 있는 경우가 많다. 받은 이미지는 `benchmark/<플랫폼>_<번호>/`에 저장한다(분석용, 상세에 쓰지 않는다).
   - 쿠팡은 자동 접속을 자주 막는다. 브라우저 도구가 있으면 그걸로 열어 상세 영역과 리뷰(낮은 별점 포함)를 캡처한다.
   - 둘 다 막히면 사용자에게 "쿠팡·네이버에서 `<키워드>` 검색 상위 상품 2~3개씩의 상세페이지 전체 캡처와 리뷰 화면"을 부탁한다. 그동안 검색 결과·블로그 리뷰로 확인 가능한 것부터 정리한다.
   - 직접 보지 못한 상세는 분석했다고 쓰지 않는다. `benchmark.md`에 "검색 결과 기준"이라고 표시한다.
3. `references/guide.md` A의 표로 상품별 분석을 쓰고(플랫폼 칸 포함), 마지막에 **공통 패턴**, **빈틈**, **쿠팡과 네이버의 차이**(예: 쿠팡은 첫 화면에 가격·혜택, 네이버는 브랜드 스토리), **리뷰에서 나온 불만·칭찬·반복 질문**을 정리한다.
4. 벤치마킹은 구조·논리·톤을 가져오는 것이다. 경쟁사의 사진, 문장, 레이아웃 그래픽을 그대로 쓰지 않는다.

## 4단계: 기획안(brief)과 승인

`brief.md`에 이어서 쓴다.

```markdown
## 컨셉
한 줄 컨셉 / 히어로 카피 2안 / 톤(존댓말·감성형 등) / 컬러(--brand, --accent 값과 이유)
## 차별화 셀링포인트 3개
1. 결과 중심 문장 — 근거 — 벤치마킹에서 찾은 빈틈과의 연결
## 스토리보드
| # | 섹션 | 메시지(제목 카피) | 본문 요지 | 이미지 | 이미지 출처 |
```

- 섹션은 템플릿의 15개(`templates/detail_page.html`)를 기본으로 하되 `references/guide.md` B의 카테고리 우선순위에 맞게 빼고 순서를 바꾼다. 보통 10~14개.
- **이미지 출처** 칸에는 `input/파일명`, `source/images/파일명(문구 지움)`, `생성: <장면 설명>` 중 하나를 쓴다.
- 생성이 필요한 이미지 목록과 예상 장수를 따로 적는다.
- 사용자에게 컨셉, 히어로 카피 2안, 셀링포인트 3개, 생성 이미지 장수를 짧게 보여주고 진행해도 되는지 묻는다(AskUserQuestion이 있으면 히어로 카피를 선택지로). 수정 요청이 오면 brief를 고치고 다시 묻는다.

## 5단계: 이미지 준비 (`assets/`)

우선순위: **사용자 사진 → 1688 이미지 → 생성 이미지**.

- **사용자 사진**: 밝기·크롭 정도만 손본다. 누끼가 필요하면 배경 제거 도구(힉스필드 `remove_background`, 캔바 `remove-background`)를 쓴다.
- **1688 이미지**: 중국어가 박힌 이미지는 문구 없는 부분만 잘라 쓰거나, 문구 위에 템플릿 섹션 배경을 덮어 한국어 카피로 대체한다. 잘라도 중국어가 남으면 쓰지 않는다. 치수 그림은 수치를 확인해 HTML로 다시 그리거나 깨끗한 제품컷에 한국어 치수를 얹는다.
- **생성 이미지**(연출컷, 사용 장면, 히어로 배경): 아래 순서로 **쓸 수 있는 첫 번째 방법**을 쓴다. 어느 방법이든 장면은 영어 프롬프트로 구체적으로 쓰고(장소, 조명, 각도, 소품, 비율), 제품 사진을 참조로 넣어 제품이 바뀌지 않게 한다.

  **A. 힉스필드** (도구가 연결돼 있고 크레딧이 충분할 때)
  1. `balance`로 잔액을 확인한다. 만들 장면 목록·장수·예상 크레딧을 보여주고 **동의를 받고** 생성한다.
  2. 제품 사진을 `media_upload`로 올려 참조로 쓴다. 모델을 모르면 `models_explore`로 추천받고, 여러 장은 배치로 만든다.
  3. 잔액이 예상 크레딧보다 적거나, 사용자가 크레딧 사용을 거절하면 B로 넘어간다. 크레딧 충전을 먼저 권하지 않는다.

  **B. 캔바 AI 이미지** (캔바 도구가 연결돼 있을 때)
  1. 제품 사진을 `create-upload-url`로 한 장씩 올리고, 받은 mediaId를 `generate-image`의 `imageReferences`에 넣는다. 비율은 `PORTRAIT_3_4`, `SQUARE_1_1` 같은 값으로 준다.
  2. 결과는 `get-generate-image-job`으로 받는다. 캔바 요금제의 AI 사용 한도를 쓰므로 처음 쓸 때 몇 장 만들지 알리고 진행한다.
  3. 한도 초과나 오류면 C로 넘어간다.

  **C. 제미나이 이미지** (`GEMINI_API_KEY`가 있을 때)
  ```bash
  python3 <스킬 폴더>/scripts/gen_image_gemini.py check
  python3 <스킬 폴더>/scripts/gen_image_gemini.py run --ref input/제품1.jpg --ref input/제품2.jpg \
    --prompt "<장면 설명>" --aspect 3:4 --out detail-pages/<slug>/assets/hero.png
  ```
  - 참조 제품을 그대로 유지하라는 지시가 자동으로 붙는다.
  - `GEMINI_FAILED: HTTP 429 ... free_tier ... limit: 0` → 무료 키로는 이미지 생성이 안 된다는 뜻이다. Google AI Studio에서 결제(빌링)를 연결해야 쓸 수 있다고 한 줄 알리고 D로 넘어간다.
  - `GEMINI_SKIPPED_NO_KEY` → 바로 D로 넘어간다. 키를 채팅에 붙여 달라고 하지 않는다.

  **D. 생성 없이 만들기** (항상 가능, 비용 없음)
  - 누끼: 단색 배경 사진이면 직접 딴다. 배경이 복잡하면 캔바 `remove-background`(연결돼 있을 때)를 쓴다.
    ```bash
    python3 <스킬 폴더>/scripts/compose_studio.py cutout input/제품.jpg --out assets/product_cut.png
    ```
  - 스튜디오 컷: 누끼를 그라데이션 배경 위에 그림자와 함께 올린다. 색은 brief의 컬러에 맞춘다.
    ```bash
    python3 <스킬 폴더>/scripts/compose_studio.py compose assets/product_cut.png --out assets/hero.jpg \
      --size 1720x2300 --color "#2b2f36" --color2 "#111418" --floor
    ```
  - 연출 배경: 제품이 없는 배경 사진(1688 연출컷의 빈 부분, 사용자가 찍은 공간 사진, 캔바 무료 사진)을 `--bg`로 넣고 누끼를 합성한다.
  - 사용 장면은 1688 연출컷 중 중국어가 없는 것을 우선 쓰고, 부족하면 해당 섹션을 디테일 클로즈업·아이콘형 포인트 섹션으로 바꾼다.

  공통 검수: 결과를 직접 보고 원본 제품과 색·모양·구성이 다르면 버리고 다시 만든다. 손가락·글자 깨짐도 확인한다. 어떤 방법으로 어떤 이미지를 만들었는지 brief의 이미지 출처 칸에 적는다.
- 파일 이름은 템플릿 경로에 맞춘다(`hero.jpg`, `product_cut.png`, `feature1.jpg`…). 한 장 가로는 1720px(2배) 이상이 좋다.

## 6단계: HTML 제작

1. `templates/detail_page.html`을 `page.html`로 복사한다.
2. 스토리보드 순서대로 섹션을 채우고, 안 쓰는 섹션은 지우고, 필요한 섹션은 복제한다. 섹션 하나 = 업로드 이미지 한 조각이므로 `<section>` 밖에 내용을 두지 않는다.
3. `:root`의 `--brand`, `--accent`를 brief 값으로 바꾼다. 색을 더 늘리지 않는다.
4. 카피는 `references/guide.md` C를 따른다. 모바일에서 읽는다고 보고 `<br>`로 줄을 직접 끊는다.
5. 스펙표는 `source.md`의 속성 번역값을 쓴다. 모르는 칸은 비우지 말고 사용자에게 물을 목록에 넣는다.

## 7단계: 이미지로 뽑기와 검수

```bash
python3 <스킬 폴더>/scripts/render_page.py check
python3 <스킬 폴더>/scripts/render_page.py run detail-pages/<slug>/page.html --out detail-pages/<slug>/out
```

- `MISSING` → 바로 설치하지 않는다. 출력된 설치 명령을 보여주고 허락받은 것만 설치한다.
- 결과: `out/full.png`(전체 1장), `out/slices/NN_<섹션id>.jpg`(섹션별, 2000px 넘는 섹션은 나눔). 폭 기본 860px, 2배로 찍어 줄인다.
- `WARN_SIZE` → `--quality 80`으로 다시 뽑는다.

**검수는 반드시 직접 본다.** `out/slices`를 모두 열어 확인하고 문제가 있으면 고쳐서 다시 뽑는다.

- 글자 넘침·잘림, 줄바꿈 어색함, 이미지 빈칸(경로 오류), 중국어 잔존
- 생성 이미지와 실제 제품의 차이
- 섹션 제목만 이어 읽었을 때 구매 이유가 전달되는지
- `references/guide.md` E 점검(금지 표현, KC·식품용 확인, 스펙표와 고시정보 일치)

## 8단계: 전달

채팅은 짧게:

- 결과 폴더와 조각 개수, `out/full.png`를 파일로 보여준다(SendUserFile이 있으면 사용)
- 컨셉 한 줄과 셀링포인트 3개
- 이미지를 만든 방법(힉스필드/캔바/제미나이/합성)과 장수, 쓴 크레딧(썼다면). 생성을 못 해 합성으로 대체한 섹션이 있으면 그 목록
- 사용자가 확인·보완할 것: 빈 스펙, 인증 여부, 실측이 필요한 수치
- 업로드 방법: 쿠팡 Wing → 상품 등록/수정 → 상세설명 → 이미지 등록에 `slices`를 파일명 순서대로 올린다. 업로드 용량·크기 제한은 Wing 화면 안내를 따른다.

수정 요청은 `page.html`만 고치고 7단계부터 다시 한다.
